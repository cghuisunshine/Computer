01 / Core idea

One strategy, three steps

Divide and Conquer is an algorithm design technique: make smaller instances of the same problem, solve them (often recursively), and use those results to solve the original problem.

1

Divide

Split the problem into smaller subproblems.

2

Conquer

Solve each subproblem, often by applying the same algorithm.

3

Combine

Use the smaller solutions to obtain the complete solution.

Base case matters: Recursion needs a stopping rule—such as “an array of one element is already sorted” or “moving one disk requires only one move.”

Not every algorithm has an expensive combine step. In Binary Search, we only recurse into one half. In Merge Sort, we solve both halves and merge their answers. In Towers of Hanoi, two smaller moves surround one move of the largest disk.

02 / Sorting

Merge Sort

O(n log n)

Divide the array in half until only single elements remain. A one-element list is sorted. Then merge sorted lists by repeatedly choosing the smaller front element.

Interactive: split and merge

Click through the stages. Each outlined group is one subproblem.

Step 1 / 7

PYTHON
def merge_sort(arr):
    if len(arr) <= 1:
        return arr

    mid = len(arr) // 2
    left = merge_sort(arr[:mid])
    right = merge_sort(arr[mid:])

    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1

    return result + left[i:] + right[j:]

print(merge_sort([8, 3, 5, 1, 7, 2, 6, 4]))
# [1, 2, 3, 4, 5, 6, 7, 8]
T(n) = 2T(n/2) + O(n)Two recursive halves; linear-time merge at each level.
O(n log n)There are log₂ n levels and O(n) work per level.
03 / Searching

Binary Search

O(log n)

Search a sorted array. Look at the middle element. If your target is larger, discard the left half; if smaller, discard the right half. Only one half survives each step.

Interactive: find 23

Pick the half that can still contain the target. Grey cells have been discarded.

Comparisons: 1
PYTHON
def binary_search(arr, target):
    low, high = 0, len(arr) - 1
    while low <= high:
        mid = (low + high) // 2
        if arr[mid] == target:
            return mid
        if arr[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1

print(binary_search([2, 5, 8, 12, 16, 23, 38, 45], 23))
# 5 (index starts at zero)
Why so fast? Every comparison approximately halves the remaining candidates: n → n/2 → n/4 → … → 1. Thus T(n) = T(n/2) + O(1) = O(log n).

How Divide and Conquer solves Hanoi

To move n disks from A to C, using B:

  1. Divide / Conquer: Move the top n − 1 disks from A to B (using C).
  2. Move: Move the largest disk from A to C.
  3. Conquer / Complete: Move the n − 1 disks from B to C (using A).
Base case: When n = 1, move the one disk directly from source to destination. This stops the recursion.
PYTHON
def hanoi(n, source, helper, destination):
    if n == 1:
        print(f"Move disk 1: {source} → {destination}")
        return

    # 1. Move top n-1 disks out of the way.
    hanoi(n - 1, source, destination, helper)

    # 2. Move the largest disk.
    print(f"Move disk {n}: {source} → {destination}")

    # 3. Move n-1 disks onto the largest disk.
    hanoi(n - 1, helper, source, destination)

hanoi(3, "A", "B", "C")

Why does it take 2ⁿ − 1 moves?

Let T(n) be the fewest moves needed for n disks. To move the largest disk, we must first move all n − 1 smaller disks away. After moving it, those n − 1 disks must be moved back onto it. This gives:

T(n) = 2T(n − 1) + 1,   T(1) = 1

Expand the recurrence:

T(n) = 2[2T(n − 2) + 1] + 1
     = 4T(n − 2) + 3
     = 8T(n − 3) + 7
     = 2ⁿ − 1

Unlike Merge Sort, Hanoi subproblems have size n − 1, not n/2. Divide and Conquer does not always mean cutting the input in half.
3 disks → 7 moves2³ − 1 = 7
6 disks → 63 moves2⁶ − 1 = 63 (exponential growth)
05 / Big picture

Compare the algorithms

All three use recursive thinking, but the number and sizes of subproblems determine their efficiency.

AlgorithmRecursive workRecurrenceTime
Merge SortSort two halves; merge2T(n/2) + O(n)O(n log n)
Binary SearchSearch one halfT(n/2) + O(1)O(log n)
Towers of HanoiMove n−1 disks twice2T(n−1) + 1Θ(2ⁿ)

Note: for Towers of Hanoi, n represents the number of disks; for the array algorithms, n is the array length. Binary Search requires sorted data. Merge Sort's O(n log n) bound includes the usual linear-time merging.
