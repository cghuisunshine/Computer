The starting example · n = 3

Three stairs, three different routes.

Stand on the ground, labelled 0. You can move up one or two stairs. To reach stair 3, the complete possibilities are 1 + 1 + 1, 1 + 2, and 2 + 1. The order of moves changes the route: 1 + 2 visits stair 1, while 2 + 1 visits stair 2.

Choose a route and follow its actual landings

3 routes

Try 1 stair: only [1]. Try 2 stairs: [1, 1] or [2]. These give the initial answers dp[1] = 1 and dp[2] = 2. The route explorer lists every route for its selected n, including all 55 routes when n = 9.

Complete Python example · Backtracking

Try a move, explore it, then come back.

Backtracking begins at stair 0. At each position it tries +1, fully explores that choice, then tries +2. Reaching the top adds one to the counter. A choice beyond the top is skipped. The current stair is passed as an integer, so returning from the function automatically restores the caller’s stair.

Trace for 3 stairs0

Successful routes so far: 0. Gold marks a skipped move; green marks a complete route.

This trace uses the same stair count as the route explorer above. Start with 3, then select 5 to see more branches.

Complete, runnable Python

def climb(n):
    choices = [1, 2]
    count = [0]

    def visit(stair):
        if stair == n:
            count[0] += 1
            return
        for move in choices:
            if stair + move > n:
                continue
            visit(stair + move)

    visit(0)
    return count[0]


if __name__ == "__main__":
    print(climb(9))  # 55 routes

For n = 3 the counter changes 0 → 1 for [1, 1, 1], 1 → 2 for [1, 2], and 2 → 3 for [2, 1]. The attempted move from stair 2 to stair 4 is pruned. For the source’s driver example n = 9, the printed answer is 55.

Derive the recurrence · n = 5

Five routes plus three routes makes eight.

Every route to stair 5 has exactly one last move. If that move is +1, the route must previously have reached stair 4. If it is +2, it must previously have reached stair 3. Remove the final move to see a one-to-one pairing with the smaller routes.

Complete Python example · Recursive search

Break nine stairs into smaller counting questions.

The first call asks for dp[9]. It asks dp[8] and dp[7]. Then dp[8] asks dp[7] and dp[6]. The second request for dp[7] repeats the same problem. That duplication continues all the way down to the known answers 1 and 2.

climb(3) = 2 + 1 = 3
climb(4) = 3 + 2 = 5
climb(5) = 5 + 3 = 8
…
climb(9) = 34 + 21 = 55

Complete, runnable Python

def climb(n):
    if n <= 2:
        return n
    left = climb(n - 1)
    right = climb(n - 2)
    return left + right


if __name__ == "__main__":
    print(climb(9))  # 55 routes

For n = 9, this version makes 67 function calls and 33 additions to get 55 routes. A call counts one invocation, not one route. The earlier n = 5 tree has nine calls and eight routes.

Complete Python example · Memoization

Store the first answer. Reuse the next request.

The first descent is 9, 8, 7, 6, 5, 4, 3. State 3 reads base answers 2 and 1 and stores 3. State 4 then stores 5. When state 5 requests state 3 again, the cached 3 is returned without exploring its children.

Complete, runnable Python

def climb(n):
    cache = {}
    def solve(i):
        if i <= 2:
            return i
        if i in cache:
            return cache[i]
        left = solve(i - 1)
        right = solve(i - 2)
        cache[i] = left + right
        return cache[i]
    return solve(n)


if __name__ == "__main__":
    print(climb(9))  # 55 routes

With these base-case checks, n = 9 takes 15 calls, 7 additions, and 5 cache hits. Cache hits occur at states 3, 4, 5, 6, and 7. The source uses an array mem initialized with −1; this Python adaptation uses a dictionary, where an absent key means “not computed.” Both store the same answers.

Complete Python example · Bottom-up DP

Fill every table entry up to the ninth stair.

We already know dp[1] = 1 and dp[2] = 2. Fill from left to right. Before calculating dp[i], both dp[i − 1] and dp[i − 2] are available. There is no recursive descent or return sequence.

Complete, runnable Python

def climb(n):
    if n <= 2:
        return n
    dp = [0] * (n + 1)
    dp[1], dp[2] = 1, 2
    for i in range(3, n + 1):
        dp[i] = dp[i - 1] + dp[i - 2]
    return dp[n]


if __name__ == "__main__":
    print(climb(9))  # 55 routes

The list has n + 1 slots so the stair numbers can be used directly as indices. Slot 0 is unused in this implementation. Only stairs 3–9 require additions: seven transitions produce the final 55.

Complete Python example · Space optimization

Keep two answers and roll them forward.

After computing a state, the next calculation no longer needs the oldest answer. Before stair i, a means dp[i − 2] and b means dp[i − 1]. Evaluate the old sum first, then let a take the old b and b take the sum.

7(8, 13)8 + 13 = 21(13, 21)
8(13, 21)13 + 21 = 34(21, 34)
9(21, 34)21 + 34 = 55(34, 55)

Complete, runnable Python

def climb(n):
    if n <= 2:
        return n
    a, b = 1, 2
    for i in range(3, n + 1):
        a, b = b, a + b
    return b


if __name__ == "__main__":
    print(climb(9))  # 55 routes

Python evaluates the right-hand side of a, b = b, a + b using both old values. Writing a = b followed by b = a + b would overwrite the old a: (1, 2) would incorrectly become (2, 4). When the loop finishes, b is 55. The source also shows this as a, b = b, a + b; no full table is needed.

1

            

              

                The staircase problem
              


              
A small counting problem makes the whole idea visible.

            


            

              

                

                  

                    Trunk
                    What are we counting?
                  

                  ▶
                

                

                  
You have n stairs and may climb either one or two stairs per move. How many different sequences of moves reach exactly stair n? Order matters: 1 then 2 and 2 then 1 are different routes. For three stairs, the routes are 1 + 1 + 1, 1 + 2, and 2 + 1. So the answer is 3. We count routes, rather than finding the fewest moves.

                

              

              

                

                  

                    Trunk
                    Define the state
                  

                  ▶
                

                

                  
Let dp[i] mean the number of routes that end exactly at stair i. A state is the information needed to identify a smaller problem. Here, that information is just the stair number i.

                

              

              

                

                  

                    Trunk
                    Look at the last move
                  

                  ▶
                

                

                  
Every route to stair i ends with either a one-stair move from i − 1 or a two-stair move from i − 2. These two groups do not overlap, and together they contain every route. Add their counts:

                  
dp[i] = dp[i − 1] + dp[i − 2]   for i ≥ 3
dp[1] = 1
dp[2] = 2

                  
For five stairs: dp[5] = dp[4] + dp[3] = 5 + 3 = 8. The staircase sequence starts 1, 2, 3, 5, 8, 13. It is shifted by one position compared with Fibonacci starting 0, 1.

                

              

            

          


          

            
2

            

              

                Brute-force search
              


              
First make the recurrence work. Then notice the repeated work.

            


            

              

                

                  

                    Trunk
                    Enumerate choices with backtracking
                  

                  ▶
                

                

                  
Start at stair 0. Try a move of one stair, then a move of two stairs. If a move would go past n, skip it. When a route reaches exactly n, count it once. This is a depth-first exploration of possible routes.

                

              

              

                

                  

                    Trunk
                    Recursively count smaller problems
                  

                  ▶
                

                

                  
Instead of carrying every route, recursively ask for the counts at n − 1 and n − 2. Return 1 or 2 when the problem reaches a known base case. The formula is correct, but the recursion recomputes identical states. For example, solving state 5 asks for states 4 and 3. Solving state 4 asks for states 3 and 2. State 3 is now solved twice. These are overlapping subproblems.

                

              

              

                

                  

                    Trunk
                    Why does it get slow?
                  

                  ▶
                

                

                  
Each non-base call branches into two calls. The conventional upper bound is O(2ⁿ) time; the tighter growth rate is Θ(φⁿ), where φ is about 1.618. The deepest active call chain is O(n), so auxiliary space is O(n), even though the complete recursion tree has exponentially many calls.

                

              

            

          


          

            
3

            

              

                Memoization
              


              
Keep the recursive questions. Remember their answers.

            


            

              

                

                  

                    Trunk
                    Check, compute, store
                  

                  ▶
                

                

                  
Before solving state i, look in a cache. If its answer is there, return it immediately. Otherwise solve its two dependencies, add their answers, and store the result under i. A cache hit still supplies a value to the parent calculation. It skips repeated exploration; it does not remove a valid group of routes.

                

              

              

                

                  

                    Trunk
                    Top down
                  

                  ▶
                

                

                  
Begin with the target n and recursively descend to smaller problems. As calls return, their answers build larger answers. Each non-base state is expanded once. The cache and recursion stack together require O(n) space, and the work is O(n) time. The examples check base cases before looking in the cache. Base-case calls may repeat; they are already constant-time answers. The repeated branching work is what memoization removes.

                

              

            

          


          

            
4

            

              

                Bottom-up tabulation
              


              
Change the order: answer the small questions first.

            


            

              

                

                  

                    Trunk
                    Build the DP table
                  

                  ▶
                

                

                  
Set dp[1] = 1 and dp[2] = 2. Compute dp[3], then dp[4], continuing to dp[n]. When a state is reached, both dependencies are ready. Each new state needs one addition.

                

              

              

                

                  

                    Trunk
                    The vocabulary
                  

                  ▶
                

                

                  
State: the stair index i. DP table: the array holding answers. Initial states: the known values for stairs 1 and 2. State transition: the rule dp[i] = dp[i − 1] + dp[i − 2]. Evaluation order: increasing i. Memoization and tabulation are both commonly described as dynamic programming. This chapter uses the bottom-up method as its explicit DP implementation.

                

              

              

                

                  

                    Trunk
                    Time and space
                  

                  ▶
                

                

                  
There are n states, with constant work per transition: O(n) time and O(n) space. The loop avoids a recursive call stack. For n = 1 or n = 2, return immediately before creating or indexing the table.

                

              

            

          


          

            
5

            

              

                Rolling variables
              


              
A state needs only its two immediate predecessors.

            


            

              

                

                  

                    Trunk
                    Keep the necessary history
                  

                  ▶
                

                

                  
Before computing stair i, let a = dp[i − 2] and b = dp[i − 1]. Compute their sum, then move the window forward. Python's simultaneous assignment evaluates both right-hand expressions before replacing either variable.

                  
a, b = b, a + b

                  
After the update, a holds the old b and b holds dp[i]. For i = 3, (a, b) changes from (1, 2) to (2, 3). For i = 4, it becomes (3, 5).

                

              

              

                

                  

                    Trunk
                    What do we gain and lose?
                  

                  ▶
                

                

                  
The algorithm still performs O(n) work, but retains only two answer values: O(1) auxiliary space under the usual fixed-size arithmetic model. It returns the final count without preserving every earlier answer. Keep a table if later work needs that history. Python integers grow as the count increases. Strict bit-complexity analysis also charges for bigger integers and additions; the usual introductory bounds here count arithmetic operations and stored values.

                    Trunk
                    Common mistakes
                  

                  ▶
                

                

                  
Do not mix this problem with ordinary Fibonacci base values. Do not replace a before calculating a + b unless you saved the old a. Do not add counts for groups that overlap. Do not assume every DP problem minimizes or maximizes something: this one counts routes.
