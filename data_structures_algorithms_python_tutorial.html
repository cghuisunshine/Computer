AThink in structures & costsAlgorithms, invariants, and Big O+

Imagine building a music app. A playlist needs an ordered collection, an undo button needs the most recent action, and a search box needs a way to find a song quickly. Each problem suggests a different way to organize and process information.

Definition · structure + algorithm

A data structure organizes values and supports operations on them. An algorithm is a finite sequence of well-defined steps for solving a problem. The representation and the steps together determine efficiency.

Start with the operations

  1. Specify inputs and outputs. For a search: a collection and a target go in; an index or “not found” comes out.
  2. Write a simple correct solution. Try a small example by hand.
  3. Count the work. What happens as the input size grows?
  4. Choose a representation. Can you reduce repeated scans or expensive moves?
  5. Check edge cases. Include empty inputs, one value, duplicates, and missing values.

One loop versus nested loops
def total(values):
    result = 0
    for value in values:       # n additions
        result += value
    return result

def all_pairs(values):
    pairs = []
    for left in values:
        for right in values:  # n * n pairs
            pairs.append((left, right))
    return pairs

print(total([2, 4, 6]))              # 12
print(len(all_pairs([2, 4, 6])))     # 9
Why are these costs different?
  1. The outer loop runs n times.
  2. The inner loop runs n times for each outer iteration.
  3. There are n × n append operations, so time is O(n²).
  4. The returned list also stores n² pairs: O(n²) output space. The total function needs O(1) auxiliary space.
Common trap · a loop does not automatically mean O(n)

A loop that halves its remaining work can be O(log n). Two separate linear loops cost O(n + n) = O(n), while two fully nested linear loops cost O(n²). Treat arithmetic and comparisons as constant cost in these beginner analyses; huge integers and long string keys can change that model.

Worked example · count words
def count_words(words):
    counts = {}
    for word in words:
        counts[word] = counts.get(word, 0) + 1
    return counts

print(count_words(["red", "blue", "red"]))
# {'red': 2, 'blue': 1}
Trace the changing dictionary

Start with {}. Read “red” → {"red": 1}. Read “blue” → add a second key. Read “red” again → increase its count to 2. For n words and u unique words, this uses O(n) average time and O(u) space under the constant-cost key model.

Common traps · mutation and hashability

items.sort() changes the list and returns None; sorted(items) returns a new list. Tuple immutability does not freeze mutable objects inside it. A tuple is hashable only if all its members are hashable. Lists cannot be dictionary keys or set members.

Linked lists: follow the next reference

Each node stores a value and a reference to the next node. The final reference is None. There is no direct access to the kth node: you must follow links from the head.

10→20→30→None
Build and traverse a singly linked list
class Node:
    def __init__(self, value, next_node=None):
        self.value = value
        self.next = next_node

head = Node(20, Node(30))
head = Node(10, head)            # prepend in O(1)

def linked_values(head):
    result = []
    current = head
    while current is not None:
        result.append(current.value)
        current = current.next
    return result

print(linked_values(head))      # [10, 20, 30]
Operation on a singly linked listCostCondition
Prepend / remove headO(1)Head reference is available
Find a value / access kth nodeO(n)Must traverse links
Insert after a known nodeO(1)Finding that node can still cost O(n)
Append at tailO(1) with tail; O(n) withoutMaintain a tail reference for fast append
Common trap · choosing a linked list everywhere

Fast insertion assumes you already have the relevant node. Python lists usually offer simpler code and better locality. For queues, use deque. For a stack, guard against popping an empty container: both list and deque raise IndexError.

Reference: collections.deque.

DTrees, heaps & graphsModel hierarchies, priorities, and connections+

Trees and binary search trees

A rooted tree has a root and parent–child relationships without cycles. A binary tree gives each node at most two children. In our binary search tree (BST), every left-subtree value is smaller and every right-subtree value is larger; duplicates are ignored.

BST search and inorder traversal
class TreeNode:
    def __init__(self, value, left=None, right=None):
        self.value = value
        self.left = left
        self.right = right

def bst_contains(root, target):
    current = root
    while current is not None:
        if target == current.value:
            return True
        if target < current.value:
            current = current.left
        else:
            current = current.right
    return False

def inorder(root):
    if root is None:
        return []
    return inorder(root.left) + [root.value] + inorder(root.right)

tree = TreeNode(8,
    TreeNode(3, TreeNode(1), TreeNode(6)),
    TreeNode(10, right=TreeNode(14)))
print(bst_contains(tree, 6))     # True
print(inorder(tree))            # [1, 3, 6, 8, 10, 14]
Search follows one path

Searching for 6: compare with 8 → go left; compare with 3 → go right; compare with 6 → found. Search costs O(h), where h is tree height. Balanced trees have O(log n) height; a chain-shaped BST has O(n) height. The readable inorder example copies lists through concatenation: up to O(n²) time on a skewed tree. A single shared output list avoids this repeated copying.

Heaps: efficiently retrieve the smallest item

A min-heap has a parent no greater than either child. Only the smallest element at index 0 is guaranteed; the entire list is not sorted. In the array representation, children of index i are at 2i + 1 and 2i + 2.

Priority queue with heapq
import heapq

jobs = [(3, "write report"), (1, "fix outage"), (2, "reply")]
heapq.heapify(jobs)                  # O(n)
heapq.heappush(jobs, (0, "urgent"))  # O(log n)

print(jobs[0])                      # (0, 'urgent')
print(heapq.heappop(jobs))           # (0, 'urgent')
print(heapq.heappop(jobs))           # (1, 'fix outage')
Common trap · equal priorities

Tuples compare later fields when priorities tie. For jobs whose objects cannot be ordered, use (priority, sequence_number, job) to avoid comparing the job objects. Peek costs O(1); push/pop cost O(log n).

Graphs: relationships beyond a hierarchy

A graph contains vertices (nodes) and edges (connections). Graphs can be directed or undirected, weighted or unweighted. An adjacency list maps each node to its neighbors. For this tutorial, every vertex has an entry; the demo graph is undirected and unweighted.

Breadth-first search and iterative depth-first search
from collections import deque

graph = {
    "A": ["B", "C"],
    "B": ["A", "D"],
    "C": ["A", "D", "E"],
    "D": ["B", "C"],
    "E": ["C"],
}

def bfs(graph, start):
    seen = {start}
    queue = deque([start])
    order = []
    while queue:
        node = queue.popleft()
        order.append(node)
        for neighbor in graph[node]:
            if neighbor not in seen:
                seen.add(neighbor)  # mark when enqueued
                queue.append(neighbor)
    return order

def dfs(graph, start):
    seen = {start}
    stack = [start]
    order = []
    while stack:
        node = stack.pop()
        order.append(node)
        for neighbor in reversed(graph[node]):
            if neighbor not in seen:
                seen.add(neighbor)
                stack.append(neighbor)
    return order

print(bfs(graph, "A"))         # ['A', 'B', 'C', 'D', 'E']
print(dfs(graph, "A"))         # ['A', 'B', 'D', 'C', 'E']

Why BFS is O(V + E)
  1. Each discovered vertex is queued once because we mark it immediately.
  2. Each adjacency list is scanned once when its vertex is processed.
  3. In an undirected graph each edge appears twice, which changes only a constant factor.
  4. Thus traversal is O(V + E) time and O(V) auxiliary space under average constant-cost set operations. Only the reachable component is visited.

BFS discovers shortest paths by number of edges in an unweighted graph. DFS explores with a stack and is useful for reachability and deeper searches; it does not generally find shortest paths. For nonnegative weighted edges, learn Dijkstra’s algorithm next.

Reference: heapq documentation.

ESearching & sortingFind a value; put values in order+

Linear search: no ordering required

Scan until the target is found
def linear_search(values, target):
    for index, value in enumerate(values):
        if value == target:
            return index
    return -1

print(linear_search([9, 2, 7], 7))  # 2
print(linear_search([], 7))         # -1

Worst-case time is O(n); best-case time is O(1); auxiliary space is O(1). No sorting is required.

Binary search: halve a sorted interval

Iterative binary search · inclusive bounds
def binary_search(values, target):
    low, high = 0, len(values) - 1
    while low <= high:
        mid = (low + high) // 2
        if values[mid] == target:
            return mid
        if values[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1

print(binary_search([2, 4, 7, 9, 12, 15, 18], 12))  # 4
print(binary_search([2, 4, 7], 5))                   # -1
Correctness · the search interval invariant
  1. Initially every possible position lies in [low, high].
  2. If the middle value is too small, sorted order means every value at or before mid is also too small; discard that half.
  3. If it is too large, discard mid and all positions after it.
  4. Each unsuccessful comparison strictly shrinks the interval. Equality returns a valid index; an empty interval proves absence.
  5. After k halvings at most n / 2ᵏ candidates remain, giving O(log n) worst-case time and O(1) auxiliary space.

Common trap · hidden preparation costs

Binary search requires ascending sorted input and fast indexing. Sorting once costs O(n log n) in the worst case; sorting before a single lookup can be slower than a scan. With duplicates, this version returns a matching index, not necessarily the first one. Never use values[-1] as a “not found” result: -1 is a valid Python index.

Insertion sort: grow a sorted prefix

For each new item, shift larger values to the right, then insert it into the gap. Before each outer iteration, the prefix to the left is already sorted.

Stable insertion sort
def insertion_sort(values):
    result = values.copy()
    for i in range(1, len(result)):
        key = result[i]
        j = i - 1
        while j >= 0 and result[j] > key:
            result[j + 1] = result[j]
            j -= 1
        result[j + 1] = key
    return result

print(insertion_sort([7, 3, 5, 2]))  # [2, 3, 5, 7]

Merge sort: divide, sort, combine

Merge sort with a fresh output list
def merge_sort(values):
    if len(values) <= 1:
        return values.copy()
    mid = len(values) // 2
    left = merge_sort(values[:mid])
    right = merge_sort(values[mid:])
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    result.extend(left[i:])
    result.extend(right[j:])
    return result

print(merge_sort([7, 3, 5, 2]))      # [2, 3, 5, 7]
Why merge sort is O(n log n)

Splitting in half creates O(log n) levels. Merging processes O(n) total items at each level, so total work is O(n log n). This implementation has O(n) peak auxiliary space including temporary slices, plus O(log n) recursion depth; allocations over the whole run are greater than peak memory.

Merge sort aboveO(n log n)O(n log n)O(n log n)O(n) peak

FRecursion & algorithm patternsGreedy choices, backtracking, and dynamic programming+

Recursion: solve a smaller instance

A recursive function calls itself on a smaller problem. A base case stops recursion; a progress measure proves that the calls reach it.

Factorial with a base case
def factorial(n):
    if n < 0:
        raise ValueError("n must be nonnegative")
    if n <= 1:
        return 1
    return n * factorial(n - 1)

print(factorial(4))   # 24

Trace: 4 × factorial(3) → 4 × 3 × factorial(2) → 4 × 3 × 2 × 1 = 24. This makes O(n) calls and uses O(n) stack space; large integer multiplication has additional cost. Python limits recursion depth, so loops are often better for deep linear work.

Greedy choices need a reason

To select the most non-overlapping half-open intervals [start, end), choose the earliest finishing compatible interval. Assume every interval has start < end.

Greedy interval scheduling
def select_intervals(intervals):
    chosen = []
    end = float("-inf")
    for start, finish in sorted(intervals, key=lambda interval: interval[1]):
        if start >= end:
            chosen.append((start, finish))
            end = finish
    return chosen

print(select_intervals([(0, 3), (1, 2), (2, 4), (3, 5)]))
# [(1, 2), (2, 4)]
Exchange argument · why earliest finish works

Take an optimal schedule. Replace its first interval with the earliest-finishing interval. The replacement finishes no later, so all later intervals remain feasible and the count is unchanged. Repeat this argument on the remaining intervals. Sorting dominates: O(n log n) time.

Dynamic programming: name the state first

A child climbs n stairs, taking 1 or 2 steps at a time. Let ways(i) count ways to reach stair i. The last move comes from i − 1 or i − 2, so ways(i) = ways(i − 1) + ways(i − 2). There is one way to take zero steps: do nothing.

Bottom-up DP with only two stored states
def climb_stairs(n):
    if n < 0:
        raise ValueError("n must be nonnegative")
    previous, current = 1, 1    # ways(0), ways(1)
    for _ in range(2, n + 1):
        previous, current = current, previous + current
    return current             # also 1 when n == 0

print([climb_stairs(n) for n in range(6)])
# [1, 1, 2, 3, 5, 8]
State → recurrence → base cases → evaluation order

For 4 stairs, the count is ways(3) + ways(2) = 3 + 2 = 5. Evaluating each state once takes O(n) additions and O(1) stored integer variables. Integer sizes grow with n, so that is a unit-cost model, not a constant bit-space guarantee.

Backtracking: choose, explore, undo

Generate all subsets
def subsets(values):
    answers = []
    path = []

    def visit(index):
        if index == len(values):
            answers.append(path.copy())
            return
        visit(index + 1)          # exclude this value
        path.append(values[index])
        visit(index + 1)          # include this value
        path.pop()               # undo the choice

    visit(0)
    return answers

print(subsets([1, 2]))            # [[], [2], [1], [1, 2]]
Common traps · repeated work and unjustified greed

Naive recursive stair counting repeats the same states exponentially; DP reuses them. Greedily taking the largest coin fails for coins {1, 3, 4} and amount 6: 4 + 1 + 1 uses three coins, but 3 + 3 uses two. Subset generation outputs 2ⁿ results and uses O(n2ⁿ) time and output space when copying subsets; auxiliary recursion/path space is O(n).

Example 1 · balanced brackets with a stack

Return True if (), [], and {} are correctly nested. Ignore other characters.

Balanced brackets
def balanced(text):
    matching = {")": "(", "]": "[", "}": "{"}
    stack = []
    for char in text:
        if char in "([{":
            stack.append(char)
        elif char in matching:
            if not stack or stack.pop() != matching[char]:
                return False
    return not stack

print(balanced("a * (b + [c])"))   # True
print(balanced("([)]"))            # False
print(balanced("(("))              # False
Trace + invariant

For “([)]”, push (, push [, then encounter ). The top is [, which does not match (, so reject. At each step, the stack contains unmatched opening brackets in nesting order. A final nonempty stack means an opening bracket was never closed. Time O(n), auxiliary space O(n) worst case.

Example 2 · two sum with a dictionary

Return two distinct indices whose values sum to target; return None if no pair exists. The input need not be sorted.

Remember values already seen
def two_sum(values, target):
    seen = {}
    for index, value in enumerate(values):
        needed = target - value
        if needed in seen:
            return seen[needed], index
        seen[value] = index
    return None

print(two_sum([2, 7, 11, 15], 9))   # (0, 1)
print(two_sum([3, 3], 6))           # (0, 1)
print(two_sum([4], 8))              # None
Why lookup happens before insertion
  1. Before each iteration, the dictionary contains only earlier indices.
  2. For value 7 and target 9, the needed value is 2; its index is already stored.
  3. Looking up first prevents pairing an item with itself.
  4. The one-pass solution costs O(n) average time and O(n) extra space, instead of comparing O(n²) pairs.

Example 3 · a fixed sliding window

Find the maximum sum of k consecutive values. Require 1 ≤ k ≤ len(values).

Reuse the previous window sum
def max_window_sum(values, k):
    if not 1 <= k <= len(values):
        raise ValueError("k must be between 1 and len(values)")
    current = sum(values[:k])
    best = current
    for right in range(k, len(values)):
        current += values[right] - values[right - k]
        best = max(best, current)
    return best

print(max_window_sum([2, 1, 5, 1, 3, 2], 3))   # 9
print(max_window_sum([-5, -2, -7], 2))         # -7
Trace the windows

The sums are 8, 7, 9, and 6. When the window moves, subtract the departing value and add the arriving one. This gives O(n) time. The initial slice uses O(k) temporary space in this version; replace it with sum(values[i] for i in range(k)) for O(1) auxiliary space. Initializing best to 0 would break all-negative inputs.

Example 4 · shortest path in an unweighted graph

Use BFS and record each node’s first parent. Reconstruct a path by walking backward from the goal. Require start and goal to be graph vertices.

BFS with parent tracking
from collections import deque

def shortest_path(graph, start, goal):
    queue = deque([start])
    parent = {start: None}
    while queue:
        node = queue.popleft()
        if node == goal:
            path = []
            while node is not None:
                path.append(node)
                node = parent[node]
            return path[::-1]
        for neighbor in graph[node]:
            if neighbor not in parent:
                parent[neighbor] = node
                queue.append(neighbor)
    return None

graph = {"A": ["B", "C"], "B": ["A", "D"],
         "C": ["A", "D", "E"], "D": ["B", "C"], "E": ["C"]}
print(shortest_path(graph, "A", "E"))  # ['A', 'C', 'E']
print(shortest_path(graph, "A", "A"))  # ['A']
Why the first parent is enough

BFS discovers nodes in increasing edge distance from the start. The first discovery therefore supplies a shortest route. Recording a parent only once also avoids cycles. Time O(V + E) and auxiliary space O(V) over the reachable component.

Reveal approach + complexity

On equality, remember mid and continue left with high = mid - 1. Keep the remembered answer initialized to -1. O(log n) time.

3 · Reverse a linked list

Reverse links in place, including the empty-list case.

Reveal approach + complexity

Keep previous and current references. Save current.next, redirect it to previous, then advance both. Return previous. O(n) time; O(1) auxiliary space.

4 · Count connected components

Given an undirected adjacency list, count its connected components, including isolated vertices.

Reveal approach + complexity

Start BFS from every not-yet-seen vertex; increment a component count each time a new traversal starts. Maintain one global seen set. O(V + E) time.

5 · Minimum coins

For positive integer denominations [1, 3, 4], compute the minimum coins to make amount 6. Return -1 if impossible.

Reveal approach + complexity

Use dp[0] = 0 and infinity for other amounts. For each amount a and usable coin c, minimize dp[a] with 1 + dp[a-c]. Answer 2. O(amount × number_of_coins) time; O(amount) space.

6 · Merge two sorted lists

Return one sorted list without calling sorted(). Example: [1, 4, 7] and [2, 3, 8] → [1, 2, 3, 4, 7, 8].

Reveal approach + complexity

Use two indices; take the smaller next value, then append the remaining tail. O(n + m) time and O(n + m) output space.

A repeatable problem-solving checklist

  1. Clarify: sorted input? duplicates? allowed mutation? what happens on failure?
  2. Trace: solve a tiny example by hand.
  3. Baseline: write a correct simple solution first.
  4. Improve: look for repeated scans, repeated subproblems, and a matching data structure.
  5. Explain: state an invariant or recurrence and why the algorithm terminates.
  6. Test: empty, one element, duplicates, extremes, and absent targets.
  7. Analyze: give time and auxiliary space, with case and assumptions.
